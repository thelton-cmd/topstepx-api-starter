# pine2py: Pine Script to dashboard indicator

Converts a TradingView Pine Script (v4 or v5) indicator into a Python file for the dashboard's
Indicators menu (`dashboard/indicators_ext/`). It converts your own script into lines on a chart,
drawn with the settings you pick. It adds no rules, levels or signals, and it never touches orders.

## Use it

From the kit's folder, with the kit's Python:

    .venv\Scripts\python.exe -m tools.pine2py my_script.pine -o dashboard\indicators_ext\my_script.py
    .venv/bin/python -m tools.pine2py my_script.pine -o dashboard/indicators_ext/my_script.py

Options: `--name x` (plugin name), `--print` (show the code), `--force` (overwrite a file this tool did
not write). A running dashboard picks the new file up without a restart. The dashboard also has a
"Pine Script" button in the header that does the same thing in the browser.

Every output file starts with `# generated by tools.pine2py from <title> - do not edit by hand`; the
tool and the dashboard never overwrite a file without that first line. Warnings (things that were left
out or approximated) are printed to the terminal and shown on the page; errors name the line and column.

## What is supported

- Declarations: `indicator()`/`study()` (title, overlay), `strategy()` (see below).
- Inputs: `input`, `input.int/float/bool/string/source/color` (min, max, step, options, tooltip) become
  settings in the Indicators menu. Other input kinds use their default and say so.
- Language: variables, `var`/`varip`, `:=` and `+=` etc., `if / else if / else`, `for`, `while`
  (with a loop limit), `switch`, `break`/`continue`, `if`/`switch`/`for` as values, user functions
  (one-line and block, tuple returns), tuples `[a, b] = f()`, history `x[n]`, `na`, `nz()`, `na()`,
  `?:`, `and`/`or`/`not`, v4 names without `ta.` (`sma`, `iff`...).
- Built-ins: bar series (`open high low close volume hl2 hlc3 ohlc4 hlcc4 time bar_index`), `ta.*`
  (sma ema rma wma vwma hma swma atr tr stdev variance dev bb bbw kc supertrend sar rsi macd stoch cci
  mfi wpr change mom roc cum sum median linreg rising falling highest lowest highestbars lowestbars
  pivothigh pivotlow crossover crossunder cross barssince valuewhen vwap obv), `math.*`, `str.*` basics,
  `color.*`, `barstate.*`, `timeframe.*`, calendar parts (UTC), `syminfo.mintick` (a "Tick size" setting).
- Every `ta.*` call and every user function call keeps its own state, like Pine: two
  `ta.sma(close, 20)` calls never share history, also inside functions called from different places.
- Output: `plot` (line; histogram/columns; circles/cross as markers), `plotshape`, `plotchar`,
  `plotarrow` (markers), `hline` (dotted line), `alertcondition` (markers where true), colors that
  change per bar, `offset`.

## What is not converted (reported as warnings or errors)

- `strategy()` order logic: entries, exits, sizing and risk settings are not converted. The conditions
  behind `strategy.entry/exit/close` are drawn as markers named by their id. A comment at the top of
  the file and a warning say so.
- `fill`, `bgcolor`, `barcolor`, `plotcandle`, `plotbar`, drawing objects (`label`, `line`, `box`,
  `table`...), `alert()`: skipped with a warning. Markers cannot sit at a price, so `location.absolute`
  and `plotchar` characters are approximated.
- Errors: arrays, matrices, maps, `request.security`, libraries/imports, user-defined types and methods,
  `for ... in`, `time()`/`timestamp()`.
- Calendar parts and `timeframe.*` use UTC and the candle spacing, because the dashboard has no symbol
  settings.

## Layout

- `lexer.py`, `parser.py`, `nodes.py`, `errors.py`: source to AST (`PineSyntaxError(message, line, col)`).
- `builtins.py`: tables of the supported built-ins; `codegen.py`: AST to plugin source.
- `runtime.py`: what generated code imports (na, Series, State, ta.* implementations, plot output).
- `examples/*.pine`: runnable examples (they are also the examples in the dashboard page).

Tests: `tests/test_pine2py.py` (numbers checked against the dashboard's own indicators and small
reference implementations) and `tests/test_feature_pine.py` (the dashboard routes).
